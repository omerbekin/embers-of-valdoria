# Alan: gönderim kuyruğu ve yayın (`tools/push-queue.mjs`)
> **Ne için / Güncel mi (2026-11-08):** "GitHub'a at / canlıya al" akışının TEK sahibi: komutlar, sürüm notu kuralı, worktree modu, kuyruk sağlamlığı. Güncel; komutlar araçla karşılaştırıldı. Eski Kararlar tarihçesi: `docs/archive/arch/areas/push-queue.md`.

Agent buradan başlar; aracı baştan okuma, komutu çalıştırıp `status` bak. Sürüm numarası kuralı: `docs/arch/workflow-rules.md`.

## Gönderim akışı (Ömer "GitHub'a at" / "canlıya al" derse)
1. `node tools/push-queue.mjs ready <oturum> --fixes "<oyuncu satırı>"`: satır İngilizce, en çok 140 karakter, dosya adı yok. Bu metin AYNEN oyuncunun sürüm notu olur ve sürümü artırır. Yalnız docs/araç işiyse `--internal` (not ve sürüm yok); `data/patch-notes.json` elle zaten yazıldıysa da `--internal`.
2. `push <oturum> --bg`: kuyruk temiz kopyada tam test + build, yerel 5000, `main` push, GitHub Pages ve canlı (embersofvaldoria.com, `npm run deploy:cf`) işini kendisi yapar. `ready` verip beklersen ilk `ready`den 3 saat sonra otomatik gider.
3. `npm run release` kuyruk dışı elle yoldur; normal yol kuyruk.

## Komutlar
`status`, `ready <oturum> --fixes "..."|--internal`, `push <oturum> [--bg] [--dry]` (hazır hepsini gönderir), `eod` (elle: hazır olan her şeyi hemen gönderir), `mode <oturum> <kritik|eşlik>`, `seal <oturum> <commit> ...` (dalı o commit'e mühürler, sonrası gitmez), `retry` (durmuş gönderimi yeniden), `hold on|off` (otomatik gönderimi kalıcı kapatır/açar), `notes <oturum> --fixes "..."`, `add`, `drop`, `legacy-merged`, `doctor`, `wt-open <oturum> <ad>`, `wt-close <oturum>`, `coordinator <oturum|off>` (Ömer'in konuştuğu sohbet = Lead; raporlar ona gider), `cutover` (bir kez yapıldı).
Gönderim ~25-35 dk (temiz kopyada tam test+build); bitince 5000, Pages, canlı, sonra 300 savaşlık sim `.git/push-queue-sims/<sürüm>.txt`.

## Kurallar
- Sürüm notu (oyuncu satırı, İngilizce): tek iş tek satır, en çok 140 karakter, 8 satır; fazlasını kuyruk kendisi ayıklar, gönderim durmaz. Tam metin commit gövdesinde ve `.git/push-queue-notes/<sürüm>.json`.
- Yalnız docs/araç ise `--internal` (not girmez). Mockup-only commit sürüm almaz.
- Golden: birden çok dal birleşince ya da çakışınca kuyruk yeniden üretir (`tests/golden/record.ts`).
- Kırmızıda gönderim durur ve haber verir; süre aşımı kırmızıları yük kaynaklı olabilir (dev sunucuları, paralel sim), kapatma kararı sahibinin.
- Canlı yayın: 4 deneme, aralar 20/60/120 sn; hâlâ olmazsa canlı bu derlemeyi sunuyorsa başarılı sayılır; olmazsa temiz kopyadan elle `npm run deploy:cf`.
- Mockup-only GitHub test atlama: `deploy.yml` > `scope` işi (Ömer onayladı 2026-11-02); deneme bekliyor, kural sonuç iyi olursa dokümana yazılacak.
- Push'tan önce temiz kopyada tam `npm test` + `npm run build` yeşil olmalı (kuyruk yapar); GitHub Actions tam testi tekrar koşar, kırmızıysa Pages güncellenmez.
- Modlar: sohbet etiketiyle (`mode`): [kritik] bitince onaysız `push`; [eşlik] (varsayılan) yalnız `ready`, ilk `ready`den 3 saat sonra ya da başka gönderimle gider. Otomatik gönderim `hold on` ile kapanır.
- Başka alanın dosyasına dokunan iş o sahibe devredilir (sahip listesi `docs/arch/docs-map.md`). Yeni açık soru `## Q-NEW. Başlık`; numarayı gönderim verir.
- Worktree modu: kod değiştiren sohbet `wt-open` ile kendi kopyasında çalışır (`.claude/worktrees/chat-<ad>`, dal `chat/<ad>`, kendi `npm ci`, port 5174+); asıl `game/` yazmaya kapalı. Paralel agent için `isolation` değil, sohbet dalından komutla kopya: `git -C <kopya> worktree add <game>/.claude/worktrees/agent-<ad> -b agent/<ad>`; bitince dala merge, kopya silinir (junction önce).
- Bilinen zayıflık: `ready`den sonraki commit'ler de gider (gönderim başındaki dal ucu); `seal` bunu çözer.

## Tuzaklar
- `ready` `assets/source/` klasörlerini eklemez: `assets/source/<sahip>-vfx` git'te yoksa wiki-assets 30 dk sonra kırmızı (druid-vfx, vesper-vfx). `ready` artık uyarır; çözüm `git add` + commit + yeniden ready.
- Worktree kopyası silinmeden önce `node_modules` bağlantısı (junction) silinir, yoksa asıl `node_modules` gider.
- GitHub Actions: `cancel-in-progress`; yeni push eskisinin Pages koşusunu keser, Pages son YEŞİL koşuda kalır. Mockup URL'si Pages'te `.html` ile, canlıda uzantısız.
- Pages'e `gh` yok; PowerShell `Invoke-RestMethod` ile api.github.com (iş günlüğü yetki ister, check-run notları açık).
- Bekleyici betikler log'u baştan okursa eski "durdu" satırına takılır; başlangıç satır sayısını al.
- Ağ/DNS bazen kopar (github.com, wrangler); kuyruk yeniden dener, elle müdahale gerekirse önce `status`.

  - Kırmızı raporu: test/tip hatası veren dosyalar ve kuyruktaki sahipleri (`Kırmızı (ön test): tests/x.test.ts (...) — dosya sahibi 0e746120 (kritik, yarım)`) günlüğe, `lastError`'a ve kuyruk raporuna yazılır; tam çıktı `%TEMP%\eov-out-*.txt`.
  - `push` / `eod` kendini arka plana alıp hemen döner (`--dry` hariç); özet `.git/push-queue.log`, tam çıktı `.git/push-queue.out.log`, sonuç kuyruk raporuyla sohbete gelir.
  - **Worktree modu (faz 2, Ömer 2026-10-31):** `cutover` o anki oturumları eski akış olarak kaydeder (paylaşılan kopyada bitirirler); sonra açılan sohbet koda dokunacaksa `wt-open <oturum> <ad>` ile `.claude/worktrees/chat-<ad>` + `chat/<ad>` dalı + kendi `npm ci` + kendi portu (5174+, üst klasör `.claude/launch.json` içinde `chat-<ad>`) alır.   - Gönderim (cutover sonrası): `fetch` → taban her zaman taze `origin/main` → geçici tree'de önce eski akış dosyaları, sonra her dal üç yollu birleştirilir (`merge-tree`) → tek commit → temiz kopyada sürüm + patch notes + `## Q-NEW` numaraları → aynı kapılar → push. Çakışan dal düşer (yalnız golden çakışması düşürmez, aşağıda), sohbetine bildirim gider; kırmızı dosyaların tek sahibi varsa o düşer ve kalan bir kez yeniden test edilir, sahip belirsizse hiçbir şey gitmez. Origin'de de değişmiş eski akış dosyası üstüne yazılmaz (girdi durur; elle birleştirip `legacy-merged`).
  - Gönderim sonrası: yerel main ff; eski akış yarım işi çakışıyorsa main geride kalır, sıradaki gönderimde denenir. Dallar yeni commit'e taşınır (`reset --keep`, gerekirse dosya başına üç yollu; eski uç `refs/push-queue/backup/<ad>`). Mühürden sonraki commit'ler taşınan dalın üstünde tek commit olur.
