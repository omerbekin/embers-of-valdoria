# Simülatörler, build ve yayın

> CLAUDE.md'den taşındı (2026-10-14, birebir). Genel kurallar CLAUDE.md'de; bu belge komut ayrıntısıdır. Denge simülasyonu, build/kod bölme, GitHub Pages ya da Cloudflare yayını işinden önce oku; ayrıca `docs/balance.md`, `cloudflare/README.md`.

## Build
- `npm run build` — tip kontrolü + üretim derlemesi (`dist/`). **Kod bölme (hızlı açılış, 2026-10-10):** ilk indirmede yalnızca Phaser (kendi parçası, `vite.config.ts > codeSplitting`) + ana menü; diğer sahneler `src/game/lazy-scenes.ts` yer tutucularıyla ilk gerektiğinde iner (menü hazır olunca arka planda önceden), Codex `src/wiki/open.ts`, debug menüsü `src/ui/debug-entry.ts`, multiplayer ağ katmanı `src/game/mp-net.ts`, ses modülü (main.ts) ayrı parçada. Yeni sahne = `lazy-scenes.ts > LOADERS`'a ekle; ana menüden (MainMenuScene, main.ts) sahne sınıfı ya da ağır modül (BattleScene, campaign-ui, menu-ui, endless-session, audio) statik içe aktarılmaz (hafif olanlar: `menu-text.ts`, `kv-storage.ts`).

## Testler
- **Hızlı / yavaş ayrımı (2026-10-14):** `vite.config.ts > test.projects` iki proje tanımlar: `fast` (yavaşlar hariç her şey) ve `slow` (yalnızca `vitest.slow-list.ts > SLOW_TESTS`: balance, balance-b, campaign-balance, campaign-difficulty, endless-balance, golden). `npm test` ikisini birden koşar (CI aynen her şeyi koşar); `npm run test:fast` = `vitest run --project fast` (~13 sn), `npm run test:slow` = `vitest run --project slow` (~108 sn; süreyi tek başına campaign-difficulty belirler). Tek dosya: `npx vitest run tests/<dosya>.test.ts`. Havuz `pool: 'threads'` (forks'tan ~%17 hızlı); `isolate: false` testleri kırdığı için kullanılmaz.
- Yeni bir test dosyası tek başına ~3 sn'yi aşıyorsa (denge simi, büyük kayıt karşılaştırması) `vitest.slow-list.ts`'e eklenir; test yeniden adlandırılmaz.
- `npm test` — vitest testleri (motor saflığı denetimi dahil: `src/engine` içinde Math.random/Phaser/DOM yasak)

## Simülatörler
- `npm run sim` — headless denge simülatörü (`src/sim/cli.ts`): rastgele takımlı savaşlar, iki taraf yapay zeka; sınıf kazanma oranı (4e 4; hedef bantlar `data/balance.json`: kazanma %44-56, bedelsiz temel saldırı %20-45, normal skill %15-35, durumsal destek %8-25, ultimate hazır olana kadar yaşayanlarda en az bir kez ≥%50, süre 35-50 tur; karakter karşı karakter tablosu yalnızca ezici eşleşmeleri işaretler), kompozisyon, skill kullanımı raporu. Argümansız 2 x 10.000 savaş; seçenekler: `npm run sim -- <savaş sayısı> <ilk seed> [oyuncu] [düşman]`. `tests/balance.test.ts` + `tests/balance-b.test.ts` aynı ölçümü test olarak korur.
- **Skill ağacı modu (Faz 6, 2026-10-22; `src/sim/tree-cli.ts` + `tree-sim.ts`, ön ayarlar `src/sim/tree-presets.json`):** `npm run sim -- <savaş> <seed[,seed2]> --tree <ön ayar|a|b|off> --level <N[,N2..]> [--side party|both] [--only=cls1,cls2] [--parts] [--rows=1,2] [--ult=u|r|d|l|none] [--out=dosya.json]`. Ağaç yalnızca sim sürecinde açılır (`_rules.json > enabled` false kalır). Standart simle aynı takım + dizilim; her birim o level'ın stat puanlarını ana stata dağıtmış (item yok). Her level için aynı seed'lerle **ağaçsız referans** + ön ayarın yönleri otomatik koşulur. `--side party` = yalnızca oyuncu tarafı ağaçlı (güç artışı; class kazanma = oyuncu tarafındaki class), `both` = iki taraf ağaçlı (sınıf eşitliği). `--parts` = evolve / ult kolu / Mastery bar etkisiz varyantları da (katkı = tam - kapalı). Ön ayarlar: `focus` (varsayılan: vekil satırları `_rules.json > debugFocus` yoksa 1+2, ult kolu debugFocus yoksa `u`, a ve b), `proxy` (sefer / Endless vekiliyle birebir), `focus-noevolve/-noult/-nobar`, `rows-01/12/23/31`; `a` / `b` = focus tek yön. Rapor: genel (oyuncu kazanma, bitmeyen savaş, ort. tur, karşı tarafın kontrol altında başlattığı tur payı + durum kırılımı), SINIF FARKI (ağaçsız / a / b, a-ağaçsız, b-ağaçsız, a-b; hedef +20..+25 ve |a-b| <= 5 işaretli), parça katkısı, build özeti, skill payı kayması (>= 5 puan ya da bedelli %40+), MP tükenmesi, düğüm tetiklenmesi (treeProc; ölü düğüm = alınmış, tetikli fx'i olan ama hiç tetiklenmeyen; sürekli sayı yamaları sayılmaz). Ham JSON `--out` yoluna (yoksa işletim sisteminin geçici klasörüne), yol en son satırda. Notlar: odaklı build ult kolunu önce doldurduğu için **L15'te a ve b aynıdır** (yön düğümü L16'da gelir; a-b ölçümü L20+), ilk evolve L28 (sayaç 23). Sabit komutlar (scout; çıktı scratchpad'e yönlendirilir):
  - 96 duman: `npx tsx src/sim/cli.ts 96 1 --tree focus --level 15,20,25 --out=<scratchpad>/tree-96.json > <scratchpad>/tree-96.txt`
  - 300 karşılaştırma: `npx tsx src/sim/cli.ts 300 1 --tree focus --level 15,20,25,30 --parts --out=<scratchpad>/tree-300.json > <scratchpad>/tree-300.txt` (sınıf eşitliği için aynısı `--side both`)
  - 1000 ince: `npx tsx src/sim/cli.ts 1000 1,50001 --tree focus --level 15,20 --out=<scratchpad>/tree-1000.json > <scratchpad>/tree-1000.txt`; sefer `npm run sim:campaign -- 240 1 medium good --tree=a` ve aynı komut `--tree` olmadan (referans); Endless `npm run sim:endless -- 300 1 --tree=a` ve `--tree` olmadan.
  - Sefer / Endless `--tree=a|b`: oyuncu vekili her savaştan önce harcanmamış puanları odaklı kurulumla o yönde harcar (`tree-sim.ts > simAutoTreeHero`, satır / ult kolu `autoTreePlan`), ağaç o süreçte bellekte açık; referans koşuyu otomatik yapmaz (aynı komut bayraksız).
- `npm run sim:campaign` — sefer simülatörü (`src/sim/campaign.ts`): seferi baştan sona YZ ile oynar (oyuncu vekili Medium = iyi oyuncu, Easy = ortalama oyuncu), üç zorluk; düğüm başına ilk deneme kazanma, deneme sayısı, kalan can, rota bitirme. Hedefler `data/campaign/balance.json`; testler `tests/campaign-balance.test.ts`, `tests/campaign-difficulty.test.ts`. **Harita seçimi (2026-10-25):** `--map=drowned-reach` (ya da `drowned_reach`, `2`; iki modda): her koşu önce Harita 1'i aynı seed'le oynar, takım `continueToMap` ile taşınır, rapor yalnız Harita 2'nin (BAŞLANGIÇ ve KAHRAMAN KAYBI bölümleri ek); varsayılan Harita 1 çıktısı aynen. Yok sayılan kurallar: open-questions 420; test `tests/campaign-map-sim.test.ts` (yavaş).
- `npm run sim:endless` — Endless simülatörü (`src/sim/endless.ts`, CLI `endless-cli.ts`): koşuları YZ ile baştan sona oynar (iyi oyuncu vekili: ödül/dükkân/Equip best/kalıntı), dalga başına kazanma, ulaşma eğrisi, p10/p50/p90, elit/boss düşüşü, sınıf ve kalıntı etkisi; `--compare` (item'siz / kalıntısız), `--cfg=dosya.json` (veriye dokunmadan ayar denemesi). Hedef bantlar `data/endless.json > balance`; test `tests/endless-balance.test.ts`.

## Yayın
- Yayın: her değişiklik önizleme linkine yayınlanır (GitHub Pages otomatik; Cloudflare https://embersofvaldoria.com elle `npm run deploy:cf`), Ömer telefondan oynar.
- Yayın: `main` dalına push → GitHub Actions test + build → GitHub Pages (`.github/workflows/deploy.yml`). Test kırmızıysa yayın olmaz.
- Yayın (Cloudflare, ücretsiz plan, elle): `npm run deploy:cf` — build + dosya sınırı denetimi + tek `wrangler deploy`: oyun https://embersofvaldoria.com (Workers Static Assets) ve multiplayer lobisi aynı Worker'da `wss://embersofvaldoria.com/lobby` (`cloudflare/wrangler.toml`, alan adı Custom Domain olarak otomatik bağlanır). Bir kez önce: `npm --prefix cloudflare install` + `npm --prefix cloudflare exec -- wrangler login` (Ömer onaylar). Hesaba dokunmadan kuru deneme: `npm --prefix cloudflare run check`. Yerel: `cd cloudflare && npm run dev` (127.0.0.1:8787, önce `npm run build`). Adımlar ve ücretsiz plan sınırları: `cloudflare/README.md`. **Yalnızca ücretsiz plan (Ömer): ücretli Cloudflare özelliği eklenmez.**
- **Hata raporu (opt-in, 2026-10-16):** aynı Worker'da `POST /diag` -> KV `DIAG` (30 gün). Bir kez: `npm --prefix cloudflare exec -- wrangler kv namespace create eov-diag`, çıkan id `cloudflare/wrangler.toml` > `REPLACE_WITH_DIAG_KV_ID` yerine (yazılmazsa `deploy:cf` hata verir). Okuma: `npm run diag:pull`. Ayrıntı `docs/arch/diagnostics.md`.
